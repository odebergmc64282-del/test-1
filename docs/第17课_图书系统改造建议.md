# 第 17 课：从控制台示例升级为工程项目

本文件是**改造建议**，不是已经实现的项目功能。

## 先审计原程序边界

- `Book`、`Library`、菜单交互都放在单个文件中：适合演示，不利于单元测试。
- 数据保存采用逗号字符串拼接；书名或作者包含逗号会导致 `split(",")` 解析错位。
- 读档时使用 `if (parts.length >= 4)`，并不等于已经完成所有字段校验；格式损坏时可能静默丢失信息。
- `String.repeat` 等 Java 11+ API 需要与 README 的环境说明保持一致。

## 建议演进方案

1. **拆分类**：`model/Book`、`service/LibraryService`、`storage/BookRepository`、`cli/LibraryCli`。
2. **可测逻辑**：`LibraryService` 不调用 `Scanner`，也不直接写终端；输入校验和数据变更由 service 负责。
3. **持久化**：第一版可以用每行一个记录、编码安全的 JSON 或使用成熟 CSV 解析器；切忌直接 `String.split(",")` 解析真实 CSV。
4. **测试**：ISBN 重复、图书借阅与归还、空库、无效输入、保存重载、书名含逗号等。
5. **工程化**：第二轮引入 Maven、JUnit 5，再引入数据库 JDBC/MySQL。
6. **后端化**：最后通过 Spring Boot 提供 REST API，隔离 controller/service/repository。

## 验收规范

- 所有业务方法可在不启动命令行菜单的条件下测试。
- 保存重载后 ISBN、状态、非 ASCII 字符不丢失。
- 同一 ISBN 不应添加两次；无效操作有明确反馈。
- 所有核心路径都有测试，不依赖人工逐个选择菜单选项。
